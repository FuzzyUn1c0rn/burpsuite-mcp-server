# M0 investigation runbook and open decisions

This is an investigation candidate, not an accepted Repeater MVP release. The
canonical acceptance contract is orchestration `SPEC.md` / issue #2. M1–M5 have
not started. Historical PoC results do not establish this candidate's behavior.
No environment currently has completed M0 acceptance evidence.

## Adapter decision under investigation

Use supported Montoya creation and read-only project/user options exports where
available, plus public Swing identity/controls for native existing-tab work. Do
not reflect into obfuscated Burp classes or write configuration. The inherited
PoC fingerprints only editor text and destination; it does **not** yet include
configured protocol or execution settings. Its Send capture matches editor text
and service, then uses Montoya message ID. It can miss normalization or rewrites
and can misattribute identical concurrent manual sends. It is an investigation
path, not the final profile-enforcing send implementation.

The proposed edit probe assigns the identified editable JTextArea's document on
Swing's event thread after identity/fingerprint/idle checks. This is a hypothesis
about Burp's backing model. Readback alone proves only widget state. A later
`send_repeater_tab` and independently recorded fixture bytes/content must prove
model behavior before this route can be adopted. Probe errors after mutation may
mean mutation occurred: reread the tab; never blindly roll back or retry.

## Probe calls

`profile_menu_inspect` is the read-only manual-menu discovery spike. First select
the exact synthetic tab in Hex and list/capture its ID. The verifier manually
opens only that tab's gear menu, then invokes the probe without selecting a
setting. It reads `MenuSelectionManager`'s already-open root/submenu path and
public invoker/checkbox/radio/menu state. Submenu contents are read only from
visible popups already on that selected path. Each submenu popup must be an
already-materialized child of its menu and name that menu as its invoker.
The root opener must remain showing. A submenu outside the path
remains unknown, including when its contents have previously been loaded.
The inspector never opens a submenu or changes,
selects, hides, clears or restores a menu/setting. The verifier dismisses the
manually opened menu after collecting evidence.

```json
{"name":"repeater_m0_probe","arguments":{"tabId":"<exact ID>","action":"profile_menu_inspect","acknowledgement":"M0_PROFILE_MENU_DISCOVERY"}}
```

Positive ownership requires the exact selected native tab/paired owners plus a
frozen invoker path within its captured action bar, outside both editors. A
same-caption foreign menu or unproven invoker returns unknown, without nodes.
The inspector uses one approval decision for the call and checks the approval
flags again before returning data. It checks root and submenu visibility,
ownership, popup path and observed menu state during the read. Detected changes
discard the sampled nodes. These checks describe the current observation and
do not establish an atomic snapshot or detect every intervening change.
Duplicate controls and conflicting or missing exclusive selections remain
unknown. Target-capture failures return a fixed diagnostic. No semantic identifier is
inferred from an anonymous icon/class/index/position. Opener attributes and menu
labels emit exact fixed semantic tokens only; unknown text/description/tooltip,
action command, rule names and secrets are omitted. Limits:128 visited nodes,
depth6, selected path16, no raw/class-name/coordinate output. Unrecognized/custom
value controls, empty/lazy submenus and caps remain unknown. Reading a cached
public check model does not establish effective inheritance/global settings,
complete session scope, configured mode or an automatic opener. These remain
explicitly false/unsupported even on a successful discovery observation.

`model_write_bytes_auto` is the separately released M0 two-stage write experiment,
with distinct acknowledgement `M0_AUTO_BYTE_MODEL_WRITE` and the same full byte
plan fields as the manual writer below. **Native use requires the orchestrator's
separate one-write assignment after immutable review/read-only recheck.** The
implementation itself does not grant that assignment.

```json
{"name":"repeater_m0_probe","arguments":{"tabId":"<exact ID>","action":"model_write_bytes_auto","acknowledgement":"M0_AUTO_BYTE_MODEL_WRITE","expectedModelRequestSha256":"<prior full hash>","expectedTargetHostname":"127.0.0.1","expectedTargetPort":18443,"expectedUsesHttps":true,"expectedModelHttpVersion":"HTTP/2","replacementRequestBase64":"<full canonical model bytes>"}}
```

One frozen native target is used throughout a shared30s budget. Phase1 invokes
one exact synchronous event and at most one guarded setter; its monotonic
attempt/normal-return evidence survives missing phase results. Only a healthy
normal-return write with immediate exact readback or solely a readback mismatch,
callback/dispatch exit, owned popup cleanup and provider deregistration can
continue. After an explicit later EDT turn, phase2 uses a new event/provider on
the same frozen table with read-only comparison bytes and no write plan. It
compares complete bytes/service/model-version and requires healthy second
cleanup plus final target checks. A new combined fresh-context confirmation
preserves the nested immediate readback result. Setter/registration/cleanup
faults, identity/permission loss, deadline or cancellation never trigger another
setter, rollback or Send. External transport cancellation can prevent a reply;
it does not erase admitted mutation or authorize retry. The result is current
observed state, not wire/configured mode or proof of every intervening edit.

`model_read_auto` is the separately opted-in **read-only** public Swing event
experiment. Select the exact synthetic tab's Hex view first; no request cell
may be actively editing, and no menu may be open. It uses only the pre-captured
Request JTable from the paired-owner layout, attempts one button3 release popup
event, and requires the callback synchronously during that dispatch with its
input event equal to that exact object. Admission is revoked when dispatch exits.
A cloned
or retargeted event cannot authorize model reading. It returns bounded event,
popup-cleanup and native-readiness metadata. It never invokes a setter, sends,
switches focus/views/settings, retries or tries alternate mouse event forms.

```json
{"name":"repeater_m0_probe","arguments":{"tabId":"<exact ID>","action":"model_read_auto","acknowledgement":"M0_AUTO_CONTEXT_READ"}}
```

Automatic success requires a positively observed owned popup synchronously
present at dispatch return, followed by verified cleanup. An empty menu path
then is unsupported/uncertain: it cannot prove a popup will not appear later.
Deferred exact-token callbacks never read the model. A synchronous callback
followed by an absent/deferred popup cannot report cleanup confirmed. No delayed
popup is globally dismissed to rescue an unsupported lifecycle.

The native event route and popup cleanup remain unverified until independently
characterized on the exact candidate. Do not manually right-click to rescue an
automatic call: a manual callback cannot match its issued event. Existing menus
refuse before dispatch. After dispatch, only a popup with this exact table as
invoker and an unchanged positively owned menu path may be hidden/cleared; menu
takeover or unprovable ownership stops the call without closing a borrowed menu.
The total observation deadline is 30s; cancellation/deadline closes issuance even
while a public registration/dispatch accessor is blocked, although such a public
API call cannot itself be interrupted. The read-only action never writes; the
separate guarded two-stage writer requires the acknowledgement above.

Successful manual/automatic reads include exception-contained bounded native
readiness metadata. Manual writer results include actual same-callback readback
hash/length and original/replacement/service/version equality when that getter
completed consistently. These diagnostics preserve `mutation_unconfirmed` on
mismatch; a later separate fresh read does not relabel the earlier result.

`model_write_bytes` is the separately guarded M0 **local model-write** experiment.
It is enabled only by the investigation JVM property, is limited to synthetic
fixture tabs, and does not freeze the final editor_text contract. First complete
a fresh `model_read` on the exact selected Hex tab. Supply all expected fields
from that read, plus canonical standard Base64 of the full replacement request
in the Montoya model-byte representation:

```json
{"name":"repeater_m0_probe","arguments":{"tabId":"<exact ID>","action":"model_write_bytes","acknowledgement":"M0_BYTE_MODEL_WRITE","expectedModelRequestSha256":"<prior modelRequestSha256>","expectedTargetHostname":"127.0.0.1","expectedTargetPort":18443,"expectedUsesHttps":true,"expectedModelHttpVersion":"HTTP/2","replacementRequestBase64":"<canonical Base64 of complete bytes>"}}
```

Do not mix text-edit arguments with these writer arguments. Prepare explicit
known bytes without passing through a native text view, for example offline:

```python
import base64
request = (b'POST /echo?m0=byte-write HTTP/2\r\n'
           b'Host: 127.0.0.1:18443\r\n'
           b'Content-Type: text/plain; charset=utf-8\r\n'
           b'X-Variant: one\r\nX-Variant: two\r\n'
           b'Content-Length: 5\r\n\r\n' + bytes.fromhex('63 61 66 C3 A9'))
print(base64.b64encode(request).decode('ascii'))
```

The input is not HTTP/2 frames or TLS wire bytes. This probe accepts at most
262144 decoded bytes/349528 encoded characters, canonical padded Base64, ASCII
request line/headers with CRLF framing, the same HTTP/1.1 or HTTP/2 message
version, and a valid UTF8 text body. ASCII binary controls except tab/CR/LF,
Transfer-Encoding, duplicate/conflicting Content-Length, and unsupported input
are refused before mutation. Body bytes are validated without reencoding them;
no String-to-native-byte conversion is used.

Like model_read, the writer waits up to 30 seconds for a new native request
context menu on the already selected exact tab. It reuses the positive paired
Request/Response owner and frozen Hex table, public request-editor invocation
and REQUEST selection guards. It checks the complete old-model hash, actual
service and model message version, native idle state and the current call's
Repeater permission. A changed permission policy invalidates a one-time grant;
currently enabled global/Repeater allowance remains valid. No permission dialog
is opened inside the EDT callback.

The public `HttpRequest.httpRequest(service, ByteArray.byteArray(byte...))`
constructor must reproduce the proposed full bytes exactly and keep the service
and model version, or the action refuses before setter. Bounded constructor
diagnostics distinguish byte/service/version mismatches. No constructor fallback,
transcoding, map conversion or header normalization is attempted. Model version
equality does not establish configured-tab mode or ALPN; output explicitly keeps
configuredProtocolVerified false until that separate native proof is available.

Immediately before one public setRequest, the original bytes/invariants and
identity/idle/permission guards are checked again in the same EDT callback. An
atomic admission state records possible mutation before entering the void API
and prevents reentrant or late second setters. Closing can win before admission;
it cannot undo an admitted/executing setter and never blocks waiting for Swing.

Results contain metadata only. `mutation_confirmed` means the same callback's
public requestResponse getter returned the exact replacement bytes and unchanged
service/model version; it does not establish wrapper freshness by itself.
Independently inspect Hex and perform a separate fresh model_read, without
changing views, to establish the native draft. `mutation_unconfirmed` with
modelWriteAttempted/mutationMayHaveOccurred covers setter/readback/cleanup faults,
identity/permission loss, and deadline after admission. A pre-admission deadline
is not_observed with no mutation attempt. A cancelled/lost reply can still follow
an admitted setter, so read the current native model before further work.

The writer never retries, rolls back, changes settings, clicks Send, or retains
the context model handle after the callback. Active callback-local references
may remain until an entered API call returns. Provider registration and payload
references are released at the observation boundary; cleanup failure is reported
without erasing attempted-mutation evidence. No completed payload cache or
history lookup is added. Native test order after independent release: unsent-tab
read, one known-byte full model replacement, exact Hex/fresh-read validation and
zero fixture-count increase, then stale/wrong-source/permission refusal controls.
Actual wire/Send proof and verified automatic context invocation remain M0
obligations; the opt-in read-only event experiment above is not native proof.

`model_read` is a separate **read-only** first-phase public-model experiment.
List native tab IDs, select the synthetic target's desired editor view (Hex is
allowed for this metadata experiment), then start:

```json
{"name":"repeater_m0_probe","arguments":{"tabId":"<listed ID>","action":"model_read","acknowledgement":"M0_UNVERIFIED_NATIVE_MODEL"}}
```

While the call waits, the independent verifier should invoke the native context
menu inside that tab's **request editor** within 30 seconds. No request document
or expected text fingerprint is supplied to this read-only action. It arms a
temporary public ContextMenuItemsProvider and returns no extra menu items. A
context is consumed only on Swing's event thread, from Repeater, with a newer
input-event timestamp, a source inside the captured exact request view and a
REQUEST editor selection context. The whole native tab identity and request-view
binding are rechecked before and after extraction. Wrong/ambiguous/stale contexts
are rejected without model access, or reported as unobserved at the deadline.
The provider closes/deregisters on success, timeout or cancellation.
An ownership rejection can include bounded structural diagnostics: individual
tab/view identity and source-ancestry booleans, fixed public component-kind
categories, component class names capped at 160 characters and at most eight
ancestor class names. It includes no labels, component/accessibility names,
coordinates, request documents or exception text. These diagnostics do not
change the ownership predicate and do not read the rejected editor model.
Closing releases the provider's target reference and prevents publication. It
cannot interrupt a public API accessor that is already executing; an in-flight
callback may keep its local references until it returns. Close checks between
stages stop further model access when closure is observed, without locking or
waiting for Swing's event thread. This is not retroactive cancellation of an
already-entered getter.

The model observation now requires the native Repeater tool and exact target tab
already selected; it does not activate either. Both visible, unique Request and
Response anchors are required. Their lowest common ancestor and distinct child
subtrees establish the Request and Response editor owners independently of the
callback. The Request owner must contain its unique recognized selector. The
Response owner is captured through its anchor and complete parent path. Its
internal selectors are not ownership evidence: their creation, hiding or
replacement inside the unchanged Response owner does not invalidate the
independently captured Request owner. Missing/hidden/duplicate anchors or
changed anchor/owner paths still refuse; no whole-tab boundary or
callback-discovered widening is accepted.

The byte writer requires Hex before provider registration and before model
access. Its experimental idle guard captures the unique effectively showing
Send and Target controls before the callback. Their minimal shared container
must be strictly inside the native leaf and disjoint from both editor owners
in both directions. Exactly one effectively showing Cancel within that bar
must be disabled, while Send is usable. All controls, wrapper and parent paths,
exact control text and Target destination are frozen and rechecked; Target
must match the approved model service. Hidden cached controls and editor-local
Cancel controls cannot establish the bar. Missing/ambiguous ownership refuses.
Disabled Cancel is an idle hypothesis pending independent native idle→held
busy→idle characterization on those exact controls. No native idle support is
claimed from component tests. Bounded diagnostics report each failed guard's
states and ancestry without exposing target text or editor content.

For the observed null-page Hex selector layout, the Request owner must contain
exactly one visible JTable and no Response/Inspector content. The table, labels,
selectors and every parent link to the native tab are captured before the
callback and revalidated before/after model extraction. The source must belong
to that exact captured table; being elsewhere in the tab is insufficient. The
public invocation must be MESSAGE_EDITOR_REQUEST and the editor selection must
be REQUEST. Multiple, missing, replaced or reparented tables/owners and response,
viewer or table invocations refuse. This is a fixed-layout read experiment, not
proof that a JTable is a durable native model handle or that the wrapper is
correct before independent known-byte/control observations.

Only whole-model/body byte lengths and SHA-256, model service and message-version
metadata are returned. The complete model and body are capped at 256 KiB for this
experiment and checked for consistent body offset/content. No raw message,
method/path, body text, accessible names, menu labels, event, editor handle or
request/response object is stored. The context handle is used only within the
callback; post-callback lifetime is explicitly untested. The model_read action
never calls setRequest, setResponse, settings writes or a network action. It does
not explicitly switch Pretty/Raw/Hex; native selection/materialization effects
must still be observed independently, rather than assumed absent.

Compare known native Hex bytes immediately before/after and compare model body
digests with independently known bytes. Include wrong response editor, other
tab, empty context, changed identity and cancellation challenges. This proves
only model-read reachability/association if successful, not a model-backed write
or byte-preserving Send. Manual `model_read` requires the verifier's native
right-click. The separate `model_read_auto` experiment above attempts one exact
public event; its native trigger, event preservation and popup cleanup semantics
must be independently verified before automatic invocation is accepted.

With the M0 JVM property enabled, Send additionally reports
`m0CaptureDiagnostics` on a captured result, or appends
`M0_CAPTURE_DIAGNOSTICS=<JSON>` to its existing timeout error. Without the
property, these fields/probes are absent. This instrumentation leaves the exact
request matcher, dispatch, approval and wait semantics unchanged; it does not
fix normalization or prove safe attribution.

The diagnostic recorder retains at most eight same-service request comparisons
and eight Repeater response observations. It counts other armed Repeater
callbacks without saving documents or HTTP objects. Header comparisons sample
the first eight positions and explicitly flag truncation; Content-Length and
charset summaries sample at most four occurrences. Only fixed header categories,
numeric Content-Length, recognized charset categories, equality flags, lengths,
digests, message IDs and observer-relative callback times are returned. Unknown
header names/values, method/path, cookies and body text are omitted. Diagnostics
are for synthetic fixture requests; hashes are comparison evidence, not secret
redaction guarantees. A diagnostic collection failure is counted and must not
change callback pass-through or matching.

Distinguish editor/hook string UTF-16 lengths and UTF-8-encoded hashes from actual
transient `HttpRequestToBeSent.body().getBytes()` length/hash. The latter is a
Montoya hook-stage body observation, not TLS/frame capture or proof against
later extension mutation. The hook message version and sanitized request-line
version are not configured-mode/ALPN proof. `Content-Type` charset categories
describe declarations; they do not establish actual encoding.

The verifier found native H2 capture timeouts despite successful single fixture
requests and found a `café` editor body sent as Latin-1 bytes even when declaring
UTF-8. These remain M0 blockers. Current Montoya ByteArray documentation says
string conversion uses Burp's specified encoding:
https://portswigger.github.io/burp-extensions-montoya-api/javadoc/burp/api/montoya/core/ByteArray.html .
This does not prove the conversion stage in the experimental JTextArea route.
Do not assume UTF-8 JSON transport establishes native body bytes, treat an
incorrect declared UTF-8 payload as equivalent, or add guessed transcoding.
Capture each stage on this candidate before choosing an encoding/model route.

It is not a fallback for unverified configured protocol or settings.

List first, then read the returned exact tab ID/fingerprint. Duplicate names do

## Fixture oracle

`GET http://127.0.0.1:18182/` returns target records and the side-effect counter;
control traffic never increments target count. Control POST `/hold` and
`/release` gate delayed responses; `/reset` clears in-memory records/counter
only when no requests are active. The JSONL file remains append-only, so resets
must be accompanied by evidence boundaries (sequence numbers restart).

All HTTP methods are echoed. Target endpoints: `/echo`, `/delay`, `/close`,
`/large`, `/status/400` through `/status/599`, `/redirect`, `/increment`,
`/tokens`, `/authenticated`. `/tokens` issues a synthetic session cookie and
X-CSRF-Token; authenticated requests require both current values. `/increment`
changes an independently queryable counter. Redirect traffic is labeled by its
separate listener. HTTP/1 responses close connections. Transfer-Encoding and
malformed/binary requests are outside this fixture profile.

Incomplete HTTP/1 bodies (EOF before Content-Length) are rejected before a
successful target record or echo response; connection diagnostics report the
expected and received lengths. A held HTTP/2 `/delay` stream is deferred
independently so other streams on that connection can complete.
HTTP/2 reset events discard unfinished upload and queued response state for that
stream; a canceled gated stream must not close an unrelated stream's connection.

Pure fixture component checks use in-memory byte streams and a simulated H2
connection, without binding sockets or running the target:

```powershell
.venv/Scripts/python -B -m unittest discover -s test-support/repeater -p test_fixture_components.py -v
```

Records include timestamp, sequence, listener, actual negotiated TLS ALPN,
protocol, method/path, ordered repeated headers, body length/SHA-256/base64 and
HTTP/1 raw header bytes. HTTP/2 records are decoded header/body observations,
not a frame/TLS-wire capture. The fixture stores synthetic evidence; the MVP
operation registry must not retain payloads. This fixture has not yet been
executed by the implementer; the verifier must challenge its observations.

default/max 50/200; request 256 KiB UTF-8; preview default/max 4000/20000 Unicode
